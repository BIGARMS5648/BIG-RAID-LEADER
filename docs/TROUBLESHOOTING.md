# 문제 해결 가이드

## 1. 설치 / 실행

| 증상 | 확인 / 해결 |
|---|---|
| 애드온 목록에 없음 | 폴더 구조가 `Interface\AddOns\BigRaidLeader\BigRaidLeader.toc` 인지 확인 (압축 해제 시 폴더가 한 겹 더 생기는 경우가 많음). 포에버 클라이언트 폴더가 맞는지 확인 |
| "오래된 애드온" | `/run print(select(4, GetBuildInfo()))` 결과로 TOC 첫 줄 `## Interface:` 값을 바꾸거나 "오래된 애드온 불러오기" 체크 |
| `/brl` 이 동작하지 않음 | 다른 애드온이 같은 명령을 쓰는지 확인 → `/bigraidleader` 또는 `/빅레이드` 사용. 채팅창에 `[BRL] 오류` 메시지가 있는지 확인 |
| 창이 화면 밖에 있음 | 설정 > 일반 > **창 위치 초기화**, 또는 `/run BigRaidLeader.char.ui.point=nil` 후 `/reload` |
| 글자가 깨짐/안 보임 | 한국어 클라이언트가 아니면 기본 글꼴에 한글이 없을 수 있음 |
| Lua 오류 창 | 설정 > 데이터 관리 > **오류 기록 보기**에서 내용을 복사해 개발자에게 전달. 애드온 내부 오류는 기능 단위로 격리되어 다른 기능은 계속 동작합니다 |
| 무엇이 문제인지 모르겠음 | `/brl 진단` (설정 > 호환성 > **자가 진단**) 결과를 복사해 전달. API·이벤트 지원, 거래 기록 상태, 저장 데이터 무결성, 정산 잔액, 최근 오류가 한 번에 정리됩니다 |
| 버튼이 모두 비활성 / "공대장 권한 없음 · 편집 잠김" | 공격대장 전용 애드온입니다. 공대장 권한을 받거나 그룹을 나가면(사전 준비/정산) 사용할 수 있습니다 |

## 2. 거래 기록

| 증상 | 원인 / 해결 |
|---|---|
| 거래가 "확인 불가"로 기록됨 | 완료 메시지를 받지 못했고 골드/가방 수량 변화로도 판정할 수 없었거나(가방 수량 API 미지원, 같은 아이템 주고받기 등), 완료/취소 신호가 충돌했거나, 거래 중 UI 재시작. 가방/골드를 직접 확인 후 거래 로그 우클릭 > **수동 확인** (실제로 취소면 **취소로 표시**). `/brl 추적` 으로 이벤트 순서를 확인할 수 있습니다 |
| 아이템 거래가 "취소"로 기록됨 | 완료 메시지가 없고 가방 수량도 변하지 않았습니다(거래가 실제로 성사되지 않음). 실제로 성사됐다면 `/brl 추적` 내용을 확인 후 **수동 확인** |
| 거래가 기록되지 않음 | 설정 > 일반 > **거래 자동 기록**이 켜져 있는지. 아무것도 오가지 않은 취소 거래는 기록하지 않음 |
| 금액이 실제와 다름 | 거래 로그 우클릭 > **금액 정정**(사유 필수, 원본 보존). 정정 금액은 이미 연결된 금액보다 작게 할 수 없음 → 연결 해제 후 정정 |
| 거래 목적을 바꿀 수 없음 | 경매/분배에 연결된 거래는 먼저 연결을 해제해야 함 |
| 공대 목적으로 분류 불가 | 공대장(또는 그룹 밖의 세션 소유자)만 가능. 공대장이 아닐 때는 개인 거래 분류만 가능 |
| 거래 창 옆 패널이 안 보임 | 설정 > 일반/거래 > **거래 창 옆 정보 패널** 확인. 공대장(또는 그룹 밖)일 때만 표시. X 로 닫으면 그 거래 동안 숨김 |
| [분배금 입력]이 동작하지 않음 | 클라이언트가 애드온의 거래 골드 입력(`SetTradeMoney`)을 막는 경우입니다. 안내된 금액을 골드 칸에 직접 입력하세요. 거래 수락은 항상 직접 해야 합니다 |
| 분류 창이 안 뜸 | 전투 중에는 표시하지 않음. 설정 > **거래 직후 목적 분류 창** 확인 |

## 3. 경매

| 증상 | 원인 / 해결 |
|---|---|
| 채팅 입찰이 인식되지 않음 | ① 우두머리 전투 중(채팅 잠금) 채팅 내용은 Secret Value → **수동 입찰** ② 금액 외 다른 말이 섞임(예: "500 갑니다") → 금액만 입력 안내 ③ 설정 > 입찰 인식 채널 ④ 공대원이 아니면 거부(입찰 내역에 사유) |
| "같은 금액 입찰" 거부 | 같은 금액이면 먼저 입찰한 사람이 우선입니다 |
| 경매 시작이 안 됨 | 이미 진행 중인 경매가 있거나 공대장 권한이 아님 |
| 연속 경매가 다음 경매를 시작하지 않음 | 전투 중에는 보류합니다(채팅에 안내). 대기열이 비었거나 [자동 시작 취소]를 눌렀는지 확인 |
| "입찰 제한" 거부 | 설정 > 경매/정산 > 미수금 입찰 제한 기준 이상 미납. 0 으로 바꾸면 끔. 공대장은 수동 입찰로 예외 처리 가능 |
| 재접속 후 경매가 "종료(확정 대기)" | 접속이 끊긴 경매는 자동으로 일시 중단됩니다. 입찰 내역을 확인하고 낙찰 확정 또는 유찰/재경매 |
| 수금 연결 시 "완료가 확인되지 않은 거래" | 확인 불가 거래는 수동 확인 후 연결 |
| "초과 입금" 경고 | 미수금보다 큰 금액. 확인 시 초과 입금으로 기록되고 상태가 "초과 입금"으로 표시 |

## 4. 정산

| 증상 | 원인 / 해결 |
|---|---|
| 분배 가능 금액이 생각보다 적음 | 확정 정산은 **실제로 연결된 수금액**만 사용. 미수금, 낙찰에 연결하지 않은 수금(경고 표시), 환불 필요 금액은 제외됨 → 낙찰·수금 탭에서 연결 |
| "합계 불일치" 오류 | 정상 데이터에서는 발생하지 않아야 함. 설정 > 데이터 관리 > 무결성 검사 결과와 함께 제보 |
| "공제 합계가 총수입 초과" | 운영비/공제/수수료/예비금/보너스를 줄이세요 (음수 분배 방지) |
| 설정을 바꿀 수 없음 | 확정(잠금)된 정산 → **잠금 해제**(사유) 후 수정, 다시 확정 |
| 지급 연결 시 "대표 수령" 확인 | 거래 상대가 분배 대상과 다를 때. 파티 대표에게 한 번에 준 경우 확인 |
| 같은 거래로 여러 명 지급 불가 | 연결 합계는 거래 금액을 넘을 수 없음(중복 지급 방지). 금액을 나누어 연결하세요 |
| 최종 잔액 확인 실패 | 장부 밖에서 골드가 오갔거나(우편 등) 미연결 거래가 있음 → 수동 장부 기록 또는 거래 연결 |

## 5. 공격대 운영

| 증상 | 원인 / 해결 |
|---|---|
| 준비 확인/풀링/파티 이동/초대가 안 됨 | 전투 중에는 게임이 막습니다. 공대장 권한 확인 |
| 풀링 버튼을 누르면 확인 창이 뜸 | 풀링 판정이 "보류"(사망자/준비 안 됨)입니다. 사유를 확인하고 "그래도 풀링"을 누르면 시작합니다 |
| 풀링 판정이 계속 "주의" | 준비 확인/전투 준비를 5~10분 안에 다시 하거나, 역할 화면에서 탱커를 지정하세요 |
| 전멸 복구 창이 안 뜸 | 우두머리 전투 실패(ENCOUNTER_END) 후 전투가 끝나야 표시. 설정 > 일반 > 전멸 복구 창 확인. `/brl 복구` 로 직접 실행 |
| 영혼석 보유자가 안 보임 | 버프 이름이 다를 수 있음 → 설정 > 버프 키워드 보완에 `SOULSTONE` 키워드 추가 |
| [준비 적용] 후 편성이 안 바뀜 | `보스:<보스 이름>` 이름의 편성 템플릿이 있어야 불러옵니다. 실제 파티 이동은 "파티에 적용" 확인 후 진행 |
| 공유 문자열 가져오기 실패 | 문자열 일부만 복사되면 체크섬 불일치로 거부됩니다. `BRL:share_` 로 시작하는 전체를 다시 복사하세요 |
| 공지가 늦게 나감 | 우두머리 전투 중 채팅 잠금 → 잠금 해제 후 자동 전송 (상태 표시줄 "채팅 제한 중") |
| 징표가 지정되지 않음 | 징표 바 버튼을 직접 클릭해야 함(보호 기능). 대상 선택 여부, 권한 확인. 전투 중에는 징표 바를 열 수 없으니 미리 열어 두기 |
| 버프가 "확인불가" | 전투 중 또는 Secret Value. 전투 밖에서 재검사 |
| 버프가 있는데 X 로 표시 | 포에버의 버프 이름/ID가 기본 데이터와 다름 → 설정 > **버프 키워드 보완** |
| 다른 공대원 내구도가 "?" | 게임 API로 다른 사람 내구도는 볼 수 없습니다. 수동 점검 항목을 사용하세요 |
| 보스 이름이 "미확인" | 공식 정보 미공개. 보스 공략에서 이름 변경, 또는 전투 전 **현재 보스** 지정 → 전투 시작 시 게임 이름으로 자동 갱신 |

## 6. 데이터 복구

1. 설정 > 데이터 관리에서 백업 목록 확인 (하루 1회 자동, 정산 확정/복구/마이그레이션 전 자동)
2. 백업 선택 > **백업 검증** → **백업으로 복구** (현재 상태는 "복구 직전 자동 백업"으로 보관)
3. 장기 보관: **전체 백업 문자열**을 복사해 메모장에 저장 → 필요 시 **백업 문자열로 복원**
4. 보관한 세션은 설정 > 세션 보관에서 **복원** (원래 ID 그대로). 손상 여부는 **검증**으로 확인
5. 저장 파일 직접 복구: 게임 종료 후 `WTF\Account\<계정>\SavedVariables\BigRaidLeader.lua.bak` 을 `BigRaidLeader.lua` 로 복사 (게임이 만드는 이전 버전)

## 알려진 제한 사항

1. **실제 포에버 클라이언트에서 검증하지 않았습니다.** 모의 환경 자동 테스트만 수행했습니다. ([TEST_PLAN.md](../TEST_PLAN.md))
2. 지하 심굴/하이잘 정상의 우두머리 이름·기술·전리품은 공식 미공개라 "미확인" 표시. 오닉시아는 오리지널 기준.
3. 버프 판별 데이터(주문 ID/이름)와 야영지 시설명은 미검증/비공식 번역. 키워드 보완 기능으로 대응.
4. 우두머리 전투 중(채팅 잠금) 채팅 입찰 인식, 채팅 공지가 불가 → 수동 입찰, 대기열 전송.
5. 다른 공대원의 마법부여/저항 장비/시약/탄약/물약은 API로 확인 불가 → 수동 점검.
6. 징표는 보안 버튼 직접 클릭으로만 지정. 모든 대상 징표 일괄 해제 기능 없음(대상별 해제, 월드 징표는 전체 해제 가능).
7. 우편/경매장 골드는 자동 기록되지 않음 → 장부 수동 기록.
8. 플레이어 식별은 이름-서버 기준. 캐릭터 이름 변경/서버 이전 시 과거 기록과 연결되지 않음 (GUID 난독화 대응).
9. WoW 애드온은 파일을 직접 쓸 수 없어 내보내기는 복사 창으로 제공.
10. 거래 직후 분류 창은 전투 중 표시하지 않음 (거래 로그에서 분류).
11. 파티 이동 적용은 한 명씩 진행하므로 40인 전체 재편성은 수십 초 걸릴 수 있음.
12. 공격대장 전용: 공대원/부공대장용 화면과 애드온 간 통신이 없습니다. 공대원 안내는 채팅/귓속말로 합니다.
13. 거래 창 골드 자동 입력은 클라이언트가 막을 수 있으며, 거래 수락은 항상 직접 해야 합니다.
14. GDKP 정책: 북미/유럽 금지 보도, 한국 서버 적용 여부 미확인 — 운영자가 공식 정책을 확인해야 함.
